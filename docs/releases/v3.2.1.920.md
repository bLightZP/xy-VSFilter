# xy-VSFilter v3.2.1.920

Fixes render-layout configuration, output sizing, allocation failures, and frame-delivery contracts while preserving the existing ASS performance optimizations. Packages are available for **32-bit (Win32) and 64-bit (x64)**, with matching symbols and pinned dependency sources.

## Fixes since v3.2.1.910

- **Apply resolution edits only on Apply/OK.** Both More property pages stage edits, so pausing at `1` while typing `1920` cannot apply or save that intermediate resolution. Invalid input identifies the affected field and leaves the accepted layout unchanged; closing without Apply discards edits. Layout mode, dimensions, and original-size policy are committed together.
- **Validate settings at every entry point.** Custom dimensions must each be 16–12,800 pixels. API calls reject invalid sizes before changing state, and invalid saved dimensions recover to 1280×720. Renderer geometry, scale, blur work, and buffer-size checks reject unsupported work before unsafe arithmetic or oversized allocations. Explicit 8K output remains supported.
- **Correct “Render To Original Video Size.”** The option now uses the actual original video dimensions, independently of the selected logical subtitle layout. A custom 8K layout on 1080p video no longer makes this checkbox request an 8K raster surface.
- **Reduce combining-buffer memory.** The native Xy wrapper allocates combining storage only when needed, sized to the clipped bounds of the subtitle bitmaps. It no longer eagerly allocates two full-target buffers. Frames retained by a consumer keep independent, immutable pixel storage.
- **Handle allocation and rendering failures safely.** Check bitmap, Gaussian-coefficient/scratch, edge-blur, and libass-adapter allocations; reject byte-count overflow; propagate failure HRESULTs; release temporary frames and provider locks; and avoid caching failed or partially rendered output.
- **Refresh stale frames after configuration changes.** Preserve every wrapper invalidation reason, including layout, geometry, FPS, bitmap limit, alpha convention, and original-size policy. Both VSFilter and XySubFilter invalidate their local output after layout changes.
- **Clear queued consumer frames safely.** XySubFilter uses the optional consumer queue-clearing interface outside renderer/filter locks. Requests coalesce, and invalidation racing a callback or an older frame delivery schedules another clear. Consumers without the extension remain supported.
- **Preserve alpha when combining bitmaps.** Transparent gaps, pixel bytes, and frame metadata now follow the negotiated inverse-alpha or ordinary-opacity convention. Fully clipped bitmaps are skipped safely.
- **Add focused regression coverage.** Tests exercise the actual property pages and DLLs with isolated registry settings, partial typing and Apply/Cancel, native/libass output/layout combinations, forced allocation failures, 128 retained frames, both alpha conventions, static-frame invalidation, and reentrant queue clearing. Both benchmark consoles build with the shared test support.

## Validation

Release builds passed for all three DLLs and both benchmark consoles on Win32 and x64. All six DLL file/product versions are 3.2.1.920. Each architecture passed the three new layout contracts and all 34 existing renderer contracts: **74 successful contract runs** in total. All **54 fixture outputs and 2,428 credits frames per architecture** matched v3.2.1.910 in bitmap placement and visible pixel hashes, with **zero mismatches**. A 50-frame zero-lead streaming smoke test per architecture matched the full-script output; the cross-architecture comparison and Python benchmark tests also passed. Release assets include the detailed validation results, binary hashes, SHA256 checksums, matching PDB symbols, and dependency licenses/sources.

The existing parsing, caching, layout reuse, lookahead, grouping, and SIMD optimizations are retained. Offline smoke timings remained close to the control builds; this release makes no new end-to-end playback or speedup claim.

## Remaining investigation

The reported effect/transparency flicker is **not claimed fixed**. Its sample-dependent investigation remains deferred until the subtitle samples are available. These confirmed fixes also do not establish the cause of the reported madVR error. Consumer queue clearing has regression-test coverage; no new madVR playback trial was performed for this release.

For implementation details, see the [fix report](https://github.com/bLightZP/xy-VSFilter/blob/v3.2.1.920/docs/render-layout-fixes-20261030.md), [source review](https://github.com/bLightZP/xy-VSFilter/blob/v3.2.1.920/docs/render-layout-and-transparency-review-20261030.md), and [test instructions](https://github.com/bLightZP/xy-VSFilter/blob/v3.2.1.920/test/benchmark/README.md). Native rendering remains the default; the optional statically linked libass backend and its pinned dependency versions are unchanged.
